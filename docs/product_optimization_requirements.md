# 2026 世界杯智能体预测产品优化需求文档

## 1. 背景与目标

当前项目已经具备 Dixon-Coles 比分矩阵、Elo 强度修正、胜平负/大小球/让球市场派生、赛程、历史交锋、近期状态、新闻风险、FotMob 阵容和 The Odds API 赔率接入等基础能力。下一步优化目标不是让大模型凭经验给结论，而是把单场预测升级为“多维数据采集 -> 多源验证 -> 可解释建模 -> 市场赔率后验验证 -> 风险提示”的产品化分析页。

参考图片中的产品思路，单场比赛应输出以下核心结果：

- 基础对阵信息：球队排名、历史成绩、预计阵型、预计首发、基地/球场/旅行因素。
- 九维度评分：近期状态、阵容实力、球队特性与国情、战术匹配、赛事动机、防守组织度、历史交锋、外部条件、赔率验证。
- 概率预测：胜平负概率、比分概率矩阵、Top 比分、大小球概率。
- 分析总结：明确说明模型依据、关键变量和结论置信度。
- 风险提示：伤停、轮换、临场首发变化、天气、赛程疲劳、战意变化、新闻突发等。
- 赔率验证：赔率只作为验证维度，不参与预测主链路，不允许用赔率反推球队实力。

本需求文档只描述产品优化要求和实现边界，后续开发应在现有项目结构内渐进实现。

## 2. 现有项目能力盘点

项目现有能力可直接复用：

- `wc2026/models/predictor.py`：Dixon-Coles + Elo 集成模型，比分矩阵由 DC 给形状，胜平负由 Elo 拉正。
- `wc2026/markets/derive.py`：由比分矩阵派生胜平负、大小球、让球等概率。
- `wc2026/analysis/evidence.py`：历史交锋和近期战绩。
- `wc2026/analysis/strength.py`：基础实力、进攻、防守、近期状态、历史交锋综合评分。
- `wc2026/analysis/environment.py`：球场、时区、气候、旅行、宏观背景解释。
- `wc2026/analysis/fatigue.py`：赛程休息天数、转场距离、海拔压力。
- `wc2026/analysis/tactics.py`：阵型取向与方向性战术研判。
- `wc2026/data/sources/fotmob.py`：FotMob 阵容、评分、伤停、近期阵型解析。
- `wc2026/data/sources/news.py`：RSS/Google News 新闻抓取，LLM 仅做标题级风险抽取。
- `wc2026/data/sources/odds_api.py`：The Odds API 多市场赔率获取，支持 h2h、spreads、totals 等。
- `web/app.py`：Streamlit 看板，已有比分热力、证据、资讯、环境等页面能力。
- `wc2026/api/app.py`：FastAPI 已暴露 `/predict`、`/evidence`、`/news`、`/value/scan` 等接口。

需要补齐的不是重写模型，而是统一“单场赛前智能体分析”的数据契约、展示结构、验证规则和证据链。

## 3. 产品原则

### 3.1 数据优先

所有关键结论必须绑定数据来源、更新时间和可信等级。禁止输出“凭经验看好某队”“大模型认为某队更强”这类无证据结论。

### 3.2 多源验证

关键数据至少满足以下验证规则之一：

- 官方源直接确认，例如 FIFA 赛程、FIFA 排名、官方名单、官方伤停公告。
- 两个以上独立公开源一致，例如 FotMob 阵容 + 新闻源确认伤停。
- 单源可用但降级标记，例如仅新闻标题提到伤停，则标记为“待确认风险”，不得作为硬性修正。

### 3.3 赔率只做后验验证

赔率数据用于对比模型概率与市场隐含概率，发现模型偏离和价值机会。赔率不得进入基础实力、阵容实力、战术匹配、胜平负主预测链路。

### 3.4 概率表达

所有智能体输出都是概率结论，必须展示不确定性和突发因素。页面文案避免“必胜”“稳胆”“一定大球”等确定性措辞。

## 5. 单场分析页需求

### 5.1 顶部对阵信息卡

展示内容：

- 两队旗帜、中文名、英文名、综合评分。
- FIFA 排名、世界杯参赛次数、最佳成绩。
- 预计阵型、预计首发、关键球员。
- 训练基地/驻地、距离比赛球场、旅行距离、时差。
- 数据更新时间和数据完整度。

综合评分应由多个非赔率维度加权得到。赔率验证分只可单独展示，不纳入综合评分。

### 5.2 九维度评分

建议九个维度如下：

| 维度 | 权重建议 | 数据依据 | 说明 |
| --- | ---: | --- | --- |
| 近期状态 | 18% | 最近 6-10 场战绩、进失球、对手强度 | 已有 `evidence.recent_form` 可扩展 |
| 阵容实力 | 22% | Elo、球员评分、身价、关键球员可用性 | 先用 Elo + FotMob rating，身价后续补 |
| 球队特性与国情 | 8% | 大赛经验、足球文化、旅欧球员、宏观后勤 | 只做低权重背景，不直接决定胜负 |
| 战术匹配 | 12% | 阵型、攻防倾向、风格克制 | 已有 `tactics.py` 可扩展 |
| 赛事动机 | 13% | 小组出线形势、东道主、轮换概率 | 已有 `context.py` 框架 |
| 防守组织度 | 12% | DC defense、失球、零封、门将评分 | 已有 strength 防守维度 |
| 历史交锋 | 5% | H2H 胜平负与进球 | 已有 `head_to_head` |
| 外部条件 | 5% | 天气、海拔、旅行、球场、时区 | 已有 environment/fatigue |
| 赔率验证 | 5% | 市场隐含概率与模型偏差 | 只作验证与风险提示，不进预测主链路 |

页面可用雷达图或横向条形图展示。图片中的“九维度能力雷达图”和“九维度评分对比”均可作为视觉参考。

### 5.3 概率预测模块

必须展示：

- 胜平负概率分布。
- Dixon-Coles 比分预测矩阵。
- 最可能比分 Top 3/Top 5。
- 大小球概率，例如 Over/Under 2.5。
- 预期进球：`lambda_home`、`lambda_away`、总进球期望。

要求：

- 概率来自模型矩阵，不允许 LLM 直接生成概率。
- 页面说明模型是概率分布，比分 Top 只是单点概率最高，不代表确定赛果。
- 若阵容/伤停/天气数据缺失，降低结论置信度并标注。

### 5.4 赔率验证模块

展示内容参考图片中的“赔率验证（模型 vs 市场）”：

- 市场项：主胜、平局、客胜、大小球、让球等。
- decimal odds。
- 模型概率。
- 市场隐含概率，需去除或说明 bookmaker margin。
- 偏差：`模型概率 - 市场隐含概率`。
- 标签：基本一致、模型偏高、市场高估、潜在价值、风险过大。

规则：

- 偏差绝对值在 8% 内：基本一致。
- 模型概率高于市场隐含概率超过 8%：潜在价值，但需风险复核。
- 模型概率低于市场隐含概率超过 8%：市场可能高估。
- 赔率源和更新时间必须展示。
- 赔率验证不得反向改写上方预测结论，只能提示“模型与市场分歧”。

### 5.5 分析总结模块

总结文案由结构化数据生成，LLM 只负责自然语言组织，不允许编造事实。

推荐结构：

1. 主结论：胜平负倾向、总进球倾向、最可能比分。
2. 核心依据：模型概率、实力差、近期状态、阵容可用性、战术匹配。
3. 关键变量：伤停、首发、天气、旅途、战意。
4. 市场验证：赔率偏差是否与模型一致。
5. 置信度：高/中/低，以及降低置信度的原因。

### 5.6 风险提示与关键变量

至少覆盖：

- 核心球员伤停、复出但状态存疑、停赛。
- 开赛前官方首发变化。
- 小组赛末轮战意和轮换。
- 旅行距离、休息天数、连续转场。
- 天气、草皮、海拔、时差。
- 新闻突发、教练变更、内部矛盾。
- 历史交锋样本过少或年代过远。
- 赔率异常波动。

风险需要分级：

- 高：足以改变模型解释或需要重算情境修正。
- 中：影响结论置信度，但不直接改变主预测。
- 低：仅作为背景提示。

## 6. 智能体工作流

### 6.1 赛前 T-7 天

- 刷新赛程、FIFA 排名、历史数据、球队基础资料。
- 抓取新闻、伤停、最近阵型。
- 生成初版预测和风险清单。

### 6.2 赛前 T-24 小时

- 刷新新闻、天气、赔率、阵容可用性。
- 更新九维度评分。
- 标记仍未确认的数据。

### 6.3 赛前 T-2 小时

- 强制刷新官方首发、伤停、天气和赔率。
- 若关键球员状态变化，重算情境调整。
- 输出最终赛前版结论，锁定数据时间戳。

### 6.4 赛后

- 写入实际比分。
- 对比预测概率、赔率偏差和结果。
- 记录命中/偏差原因，用于回测和模型审计。

## 8. 接口建议

新增或扩展接口：

- `GET /intelligence?home=&away=&fixture_id=`：返回完整单场智能体报告。
- `POST /intelligence/refresh?fixture_id=&depth=standard|deep`：刷新指定比赛数据。
- `GET /intelligence/sources?fixture_id=`：查看本场所有证据源、更新时间、可信等级。
- `GET /intelligence/audit?fixture_id=`：查看模型概率、市场偏差、赛后结果对比。

现有 `/predict` 可保持轻量预测；新增 `/intelligence` 负责产品化聚合，不破坏现有接口。

## 9. 前端展示建议

单场页从上到下：

1. 对阵信息卡：双队资料、综合评分、数据完整度。
2. 九维度雷达图 + 横向评分对比。
3. 胜平负环图/条形图。
4. 比分矩阵热力图。
5. 大小球/让球概率模块。
6. 赔率验证表。
7. 分析总结。
8. 风险提示与关键变量。
9. 数据来源与更新时间折叠区。

视觉约束：

- 赔率验证表必须有说明：“赔率仅作为验证参考，不影响上方预测结论。”
- 风险提示要比普通说明更醒目。
- 数据缺失时不能空白，应显示“暂无官方确认/待赛前刷新”。

## 10. 模型与 LLM 边界

允许 LLM 做：

- 汇总新闻标题中的已明确信息。
- 把结构化数据组织成中文分析。
- 生成风险标签，但必须引用输入标题或数据字段。

不允许 LLM 做：

- 直接编造概率、比分、伤停、首发。
- 在无数据时补全“看起来合理”的球员名单。
- 用赔率倒推模型概率。
- 把政治/国情因素写成决定性胜负因素。

## 11. 验收标准

### 11.1 功能验收

- 单场报告可在无赔率 API key 时正常生成，只隐藏或降级赔率验证模块。
- 报告中每个核心结论都有数据来源或明确标记为模型输出。
- 赔率验证模块不会改变 `prediction.outcomes`。
- 新闻/伤停信息不足时，页面明确提示“信息有限，不做硬性修正”。
- 比分矩阵、Top 比分、大小球概率与 `derive.summarize(mat)` 一致。

### 11.2 数据验收

- FIFA 排名展示官方发布日期。
- 赛程和球场信息展示来源与更新时间。
- FotMob 抓取失败时不阻塞主预测。
- 赔率数据展示 bookmaker/regions/markets 与更新时间。
- 数据质量分低于阈值时，结论置信度自动下降。

### 11.3 回测验收

- 至少对 2014、2018、2022 世界杯进行历史回测。
- 记录 Brier score、log loss、胜平负命中率、Top score 命中率、大小球命中率。
- 分析赔率验证偏差与实际结果的相关性，但不以单场胜负作为唯一评价。

## 12. 分阶段实施建议

### 阶段 1：文档与聚合层

- 新增 `MatchIntelligenceReport` 聚合函数。
- 复用现有 predict/evidence/environment/fatigue/tactics/news/odds 能力。
- 输出 JSON，不先重做 UI。

### 阶段 2：Streamlit 单场智能体页

- 按本需求完成单场页模块。
- 增加数据来源与更新时间展示。
- 加入赔率验证表和风险提示。

### 阶段 3：临场刷新与官方首发

- 增加 T-2 小时刷新逻辑。
- 接入官方首发或可靠替代源。
- 关键球员变化触发重算和风险升级。

### 阶段 4：赛后审计

- 赛后自动写入实际比分。
- 展示模型预测、市场赔率、实际赛果对比。
- 形成可回测的数据闭环。
